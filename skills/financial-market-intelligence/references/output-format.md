# 输出格式与表述规范

本文件规定「拿到工具结果之后该怎么写」：结构、必填信息与禁止表述。目标是让每个数字都能追溯，让读者一眼看出数据的时点与局限。

## 一、通用要素（每次输出都要有）

| 要素 | 来自哪个字段 |
| --- | --- |
| 数据来源 | `source` |
| 行情时间 / 数据时点 | `timestamp`、`data_timestamp`、`last date` |
| 本次获取时间 | `retrieved_at`、`generated_at` |
| 币种与单位 | `currency`、`unit`、`unit_scale` |
| 数据状态 | `data_status`、`calculation_status`、`status` |
| 口径说明 | `formula`、`inputs`、`explanation`、`notes` |

## 二、按问题类型选择输出

| 用户问的是 | 输出 | 不要输出 |
| --- | --- | --- |
| 一个价格 | 价格 + 涨跌幅 + 市场/币种 + 行情时间 + 来源 + 「延迟行情」 | 完整行业分析 |
| 一组对比（多只股票当天表现） | 表格（代码/名称/最新价/涨跌幅/行情时间） | 单指标长报告 |
| 一个财务指标 | 数值 + 公式 + 期间 + 来源 | 10 段基本面报告 |
| 多期趋势 | 指标表（指标 | 期间… | 趋势） | 文字堆砌 |
| 基本面分析 | 7.2 的 10 段 | 买卖建议 |
| 技术面分析 | 7.3 的 9 段 | 目标价、金叉买入 |
| 图表 | 图表说明 + 文件路径 + 元数据 | 用文字描述代替图表 |
| 报告 | 报告路径 + 章节结构 + 缺失数据 | 声称已生成但无文件 |

## 三、表格规范

- Markdown 表格，第一列是项目/期间，数值右对齐。
- 比率用百分比（`46.91%`），倍数用 `x`（`0.89x`），金额带千分位并在表头注明单位（如「百万美元」）。
- 不同币种**不要混在同一列**；必要时拆表或换算成比例指标。
- 缺失一律写 `—`，**不要写 0、不要留空、不要估算**。
- 期间顺序固定为最新在左（或明确标注"由新到旧"）；财务期间不要乱序。

## 四、状态措辞

| 状态 | 推荐说法 |
| --- | --- |
| `delayed` | 「延迟行情（数据源快照）」 |
| `stale` | 「这条数据较旧，行情时间是 …」 |
| `historical` | 「已披露的历史数据」 |
| `unavailable` | 「查不到，原因是 …」 |
| `insufficient_data` | 「缺少 X 科目，无法计算」 |
| `not_applicable` | 「该公式在此情形下不适用，原因是 …」 |
| `partial`（报告/图表） | 「已生成，但缺少 …，报告中已标注」 |

## 五、禁止表述

- ✗「实时」「盘中实时价」——免费源无法证明实时，一律说延迟。
- ✗「必然上涨 / 必然下跌 / 一定会涨」。
- ✗「买入 / 卖出 / 加仓 / 减仓 / 目标价 / 评级 / 保证收益」。
- ✗「根据行业平均，该公司毛利率偏低」——本项目没有可靠行业基准。
- ✗「这个指标很优秀 / 很差」——只描述数值与变化方向。
- ✗ 用 0 或旧值填补缺失数据。
- ✗ 把期货合约价说成现货价。
- ✗ 把图表生成时间当作行情时间，或把财报披露日当作获取时间。
- ✗ 声称"图已生成/报告已生成"但返回里没有真实路径。

## 六、结尾固定声明

任何涉及数据、图表或报告的回答，结尾都应包含（可精简，但意思不能省）：

> 数据来自公开免费接口，可能存在延迟或缺失；以上内容仅为数据整理与计算，不构成任何投资、交易或税务建议。

## 七、跨机器分享

图表与报告都写在生成它的机器上（`outputs/`）。回复里给路径时要说明"本机路径，其他机器不保证可访问"；需要分享时由用户自行上传，不要假设对方能打开。
